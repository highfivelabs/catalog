# Kinds the blocked Google Cloud modules lack

Generated by `task coverage` from `modules.csv` and `resource-types.csv`; do not edit. A tracked Google Cloud module is `blocked` when one of its resource types has no stable (`v1beta1`) Config Connector kind ([`README.md`](README.md), "Status"). This page lists every such kind, ranked by how many blocked modules adding it would unblock, for config-connector-extensions to work from.

**How it ranks.** Greedily: each row is the kind that, added to the rows above it, makes the most blocked modules lack nothing; ties go to the kind more blocked modules lack, then by name. *Unblocks* lists those modules, *cumulative* counts them with the rows above. *Lacked by* counts the blocked modules that need the kind at all; *alone* the ones it is the only missing kind of. A kind is the inventory's (`gcp-resource-kinds.csv`): an `alpha` kind exists only as `v1alpha1` and needs promoting; a `none` type has no kind, and its name here is derived from the Terraform type (*proposed*). Several Terraform types can need one kind (a dataset's IAM members, bindings and access entries are all `BigQueryDatasetAccess`). A module that is unblocked still needs its chart; a chart can also port a blocked module with the missing kind refused (`docs/design.md`, "What Config Connector cannot express is refused, by name").
